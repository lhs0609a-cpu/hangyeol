# 한결 (Hangyeol)

강사에게 **교재**를 주고, 그 교재로 어떻게 가르칠지 **알려주는 도구**를 준다.

italki 는 교재를 주지 않는다. 강사는 차시당 1~2시간을 준비에 쓴다.
그 시간을 0 으로 만드는 것이 상품이다.

수업은 강사가 실시간으로 한다. 우리는 음원을 만들지 않는다 —
TTS 발음을 파는 것은 파파고와 같은 것을 파는 셈이고,
그러면 이 플랫폼을 쓸 이유가 없다. 결정 기록은 [`docs/12`](./docs/12-결정기록.md).

명세는 [`docs/`](./docs) 에 있다. 읽는 순서는 [`docs/00-INDEX.md`](./docs/00-INDEX.md).

## 배포

| | |
|---|---|
| 저장소 | https://github.com/lhs0609a-cpu/hangyeol |
| Vercel 프로젝트 | `fewfs-projects-83cc0821/samat` |
| 프로덕션 | https://hangyeol-phi.vercel.app |

`main` 에 push 하면 자동 배포된다. 빌드 설정은 루트 [`vercel.json`](./vercel.json) 에 있고,
워크스페이스 루트에서 `apps/teacher` 를 빌드한다.

프로덕션 별칭은 배포마다 바뀌지 않는 `hangyeol-phi.vercel.app` 을 쓴다.
`samat-<해시>-...` 는 배포 하나를 가리키는 주소라 다음 배포에서 낡는다 —
문서에 적어 두면 반드시 어긋난다.

Deployment Protection 은 꺼져 있다. 로그인 없이 랜딩과 `/licenses` 가 열리고,
그 밖의 화면은 `middleware.ts` 가 `/login` 으로 돌려보낸다.

### 환경 변수 — DB 를 붙이는 순서

지금 Vercel 에는 환경 변수가 하나도 없다. 그래서 신청·로그인이 503 을 준다.
붙이는 데 필요한 것은 **Supabase DB 비밀번호 하나**뿐이고, 나머지는 스크립트가 만든다.

```bash
# Supabase 대시보드 → Settings → Database 에서 비밀번호 확인 또는 재설정
node tools/db-connect.mjs '<DB 비밀번호>' --vercel --admin=me@example.com
```

이 한 줄이 하는 일:

| | |
|---|---|
| `.env` 작성 | `DATABASE_URL`(6543 풀러) · `DIRECT_URL`(5432) · JWT 시크릿 3개 · 이메일 암호화 키 2개 |
| 마이그레이션 | `prisma migrate deploy` — `DIRECT_URL` 로 붙는다 |
| 클라이언트 생성 | `prisma generate` |
| Vercel 등록 | production · preview · development 세 곳 모두 |

시크릿은 **이미 있으면 덮지 않는다.** 다시 만들면 발급된 토큰이 전부 죽는다.

`--admin` 을 빠뜨리면 `ADMIN_EMAILS` 가 빈 채로 올라간다.
비면 `requireAdmin` 이 **전부 거부**한다 — 열어 두는 쪽으로 실패하지 않는다.
그 상태를 스크립트가 끝에서 경고한다.

`.env` 는 커밋되지 않는다. 등록된 뒤에는 **재배포해야 적용된다** (`git commit --allow-empty` 로 충분).

#### 첫 관리자는 화면 밖에서 승인한다

닭과 달걀이 있다. 승인 화면은 `requireAdmin` 을 지나고,
`requireAdmin` 은 **로그인한 강사** + `ADMIN_EMAILS` 다.
그런데 로그인은 승인된 계정만 된다 — 첫 한 명을 승인할 방법이 화면에 없다.

```bash
# 1. /signup 에서 평소처럼 신청한다 (비밀번호는 본인이 정한다)
# 2. DB 접속 정보를 가진 사람이 그 계정을 승인한다
node tools/admin-approve.mjs me@example.com
node tools/admin-approve.mjs --list     # 대기 중인 신청 보기
```

두 번째부터는 이걸 쓰지 않는다. `/admin/teachers` 에서 한다 —
거기에는 신청 사유가 같이 보이고 거절 사유가 기록으로 남는다.

이 스크립트는 계정을 만들지 않는다. 비밀번호를 인자로 받으면 평문이 셸 기록에 남는다.

#### 지금 넣지 않아도 되는 것

R2(자료 서명 URL) · PG(결제) · `RESEND_API_KEY`(메일) 는 없어도
신청 → 승인 → 로그인 → 수업까지 돈다. 해당 기능을 켤 때 넣는다.

메일 발송기는 아직 없다(12번 문서 D-004). 승인해도 `notification` 행만 쌓인다.
그래서 화면은 메일을 보낸다고 말하지 않는다 — 승인되면 로그인된다고만 말한다.

### 화면 · API

강사 T-01~T-06 · **교수 플랜** · 로그인 · 설정 · 출처
관리자 지표 · 이미지 자산 · 콘텐츠 현황
학생 학습노트 홈 · 복습 카드 · **레벨 테스트** · **단어장** · **진도** · 인증 (화이트라벨)

수업 예약이 붙어 T-01 출발 패널이 실제로 동작한다 —
15분 이내 예약이 있을 때만 뜨고, 없으면 빈 자리를 남기지 않는다.

### 디자인 시스템

폰트 크기를 숫자로 쓰지 않는다. 06번 §2 가 정한 9개 역할 토큰만 쓴다.

```
display 38 · h1 23 · h2 17 · body-lg 15 · body 13.5
body-sm 12.5 · caption 11.5 · eyebrow 10
```

역할 이름은 두 앱이 같고 실제 크기만 다르다 —
강사는 콕핏(고밀도), 학생은 다이어리(한 화면에 한 가지, 본문 15px).
`packages/ui/src/tokens.css` 하나에서 나온다.

`tools/design-check.mjs` 가 빌드에서 막는다:
숫자로 박은 폰트 크기, 직접 쓴 hex 색, --shadow-toggle 밖의 그림자,
한국어 본문의 양수 letter-spacing, alt 없는 이미지, 라벨 없는 svg,
숫자와 단위 사이 공백, 시스템 용어, 사과하는 오류 문구.

### 관리자 모드

헤더 우측 토글로 **강사 화면 ↔ 관리자**를 오간다 (06번 §5 "역할 토글").
관리자 모드에서는 왼쪽에 레일이 붙어 12개 화면을 명세 번호와 함께 보여주고,
`Alt + ← →` 로 앞뒤로 넘어간다.

토글은 화면에만 영향을 준다. 권한이 아니다 —
09번 문서가 요구하는 IP 화이트리스트 + 2FA 는 아직 없고, 그건 이 토글로 대체되지 않는다.
그래서 관리자 화면은 개인정보를 일절 내보내지 않는다. 전부 집계값이다.

### 이미지는 프롬프트만 준비돼 있다

만들어야 할 이미지 **160장**(차시 슬라이드 150 · 발음 단면도 6 · 체험팩 표지 4)의
생성 프롬프트가 `/admin/images` 에 있다. 복사해서 만들고 올리면
**그 자리에 자동으로 들어간다** — 저장 키가 자산 id 에서 결정되므로 코드를 고칠 필요가 없다.

프롬프트는 지도안에서 유도한다. 지도안이 바뀌면 프롬프트도 따라 바뀐다 —
두 곳에 적으면 반드시 어긋난다.
06번 디자인 시스템의 팔레트와 톤이 프롬프트 앞에 붙어 차시마다 톤이 갈리지 않는다.

**`DATABASE_URL` 이 없으면 API 는 503 을, T-01 은 목업을 돌려준다.**

### 랜딩 사진 — 사람이 없으면 도면으로 읽힌다

italki 와 Preply 는 첫 화면부터 사람이 나온다. 강사 목록은 카드마다 얼굴이 붙어 있고,
그 얼굴이 "실제로 돌아가는 서비스다" 를 문장 없이 말한다.
우리 랜딩에는 슬라이드만 있어서 제품 소개가 아니라 도면처럼 읽혔다.

두 사이트의 사진을 가져오는 선택지는 08번 §6 이 막는다 —
남의 저작물이면서 동시에 강사 개인의 초상이다.
그래서 상업 이용이 가능한 사진 5장을 직접 골라 `apps/teacher/public/photos/` 에 넣었다.
목록·촬영자·쓰임새는 `packages/content/src/photos.ts` 에 있고 `/licenses` 에 그대로 뜬다.

**규칙 하나:** 사진 속 인물을 우리 강사나 후기로 쓰지 않는다.
라이선스가 "인물이 제품을 보증하는 것처럼 보이게 하지 말 것" 을 명시하고,
없는 강사를 지어내면 옆에 있는 시장 숫자까지 같이 의심받는다.


### 교재 — 이게 상품이다

| 항목 | 초안 | 목표 | |
|---|---|---|---|
| **차시 지도안** (그대로 읽는 대본) | **30** | 30 | ✓ |
| 이미지 자산 (프롬프트) | 160 | 160 | ✓ |
| 이미지 자산 (생성·업로드) | 0 | 160 | |
| 커리큘럼 1급 | 30차시 | 30 | ✓ |
| 교실영어 | 250 | 250 | ✓ |
| 발음 시트 | 6항목 · L1 5종 | 5 | ✓ |
| 체험수업 팩 | 4종 | 4 | ✓ |

지도안이 핵심이다. "첫 멘트부터 마무리 멘트까지 그대로 읽으면 되는 수준"(08번 §8).
이 기준을 못 맞추면 강사의 준비 시간이 0 이 되지 않는다.

1급 30차시 전부 작성했다. 강사 대사 708줄, 막힘 대응 33개,
차시별 강사 실수 90개, 모국어별 주의사항 150개.

전부 AI 초안이고 한국어교원 자격 2급 검수를 거쳐야 한다.
검수 전에는 실제 수업에 쓰지 않는다. 2급(31~70차시)은 같은 밀도로 이어 쓴다.

테스트가 지도안이 대본인지 검사한다 — 모든 블록에 강사가 읽을 말과
학생이 말할 것이 있어야 하고, 드릴에 반복 지시가, 마무리에 리포트 지시가
있어야 통과한다. 커리큘럼 30차시 중 하나라도 지도안이 없으면 실패한다.

**오디오 자산은 만들지 않는다.** 결정 기록 [`docs/12`](./docs/12-결정기록.md) D-001.

### 교수 플랜 — 교재와 함께 파는 것

교재만 주면 강사는 여전히 판단해야 한다. 이 학생이 어디서 막혔는지,
오늘 복습을 길게 잡아야 하는지, 다음 차시로 넘어가도 되는지.

`/plan/[studentId]` 가 그 판단을 대신한다.

```
오늘 50분     복습 8분 · 모델 7분 · 드릴 10분 · 롤플레이 13분 · 확장 7분 · 정리 5분
              (복습 이행률 33% — 복습을 길게 잡으세요)
복습 항목     -고 싶어요 · 그런데 · -아/어 주세요   ← 지난 리포트에서 자동
중점 교정     학교를 갔어요 → 학교에 갔어요  3회
              조사 오류는 발달 단계입니다. 마무리 5분에 한 번만 짚으세요
지도안        (첫 멘트부터 마무리까지 그대로 읽는 대본)
```

근거는 전부 우리가 이미 가진 데이터다. 외부 API 를 부르지 않는다.

### 외부 자산 — 조사해서 확인한 것

무료로 보이는 것과 우리가 쓸 수 있는 것은 다르다.
공개된 한국어 TTS 모델은 **대부분 비상업**이었다.

**Piper 저장소 헤더는 MIT 지만 한국어 음성은 KSS(CC BY-NC-SA)로 학습됐다.**
코드 라이선스와 모델 라이선스는 다르다.

`tools/license-check.mjs` 가 차단 자산이 코드에 섞이는 것을 빌드에서 막고,
`/licenses` 화면이 출처 표시를 레지스트리에서 자동 생성한다.
라이선스는 90일마다 재확인한다 — 기한이 지나면 게이트가 실패한다.

## 시작하기

```bash
npm install
npm test              # 과금 TC-01~14 + 시각 유틸
npm run typecheck
```

DB 를 붙일 때:

```bash
cp .env.example .env          # DATABASE_URL · 시크릿 채우기
npm run -w @hangyeol/db generate
npm run -w @hangyeol/db migrate:dev
npm run -w @hangyeol/db seed  # 강사 1명 + 학생 5명 + 대립쌍 5종
```

두 앱을 동시에 띄운다:

```bash
npm run dev -w @hangyeol/teacher   # :3000  강사 앱 + API
npm run dev -w @hangyeol/note      # :3001  학생 학습노트
```

`EMAIL_ENC_KEY` 는 32바이트여야 한다:

```bash
node -e "console.log('base64:' + require('crypto').randomBytes(32).toString('base64'))"
```

## 이 코드베이스에서 지켜야 하는 것

11번 문서의 출시 기준과 10번 문서의 제약에서 나온 규칙이다. 여기를 어기면 사업이 깨진다.

1. **금액은 정수 KRW.** `Decimal`·`Float` 금지. `assertKrw` 로 막아둔다.
2. **시각은 전부 UTC.** 28일은 정확히 28×24시간이다. 달력 연산 금지.
3. **주기 연속성.** 새 주기의 `period_start` 는 직전 `period_end` 다. `now()` 를 쓰면
   배치 지연만큼 주기가 밀려 연간 청구 횟수가 줄어든다.
4. **배치는 멱등.** 재실행해도 결과가 같아야 한다. `closeCycle` 은 이미 닫힌 주기를
   그대로 돌려준다.
5. **런타임 TTS 금지.** 음원은 전부 사전 생성. 학생 수에 비례하는 종량과금을 만들지 않는다.
6. **자료 열람에는 반드시 `student_id`.** 학생 없이 자료를 여는 경로는 존재하지 않는다.
7. **학생 앱(`apps/note`)에 브랜드 문자열 금지.** 빌드 파이프라인에서 grep 검사로 막는다.

### 명세 자체의 확인 필요 사항

- **05번 §5 예시의 볼륨 할인 금액.** 화면 예시에 "루카스 9,700원 · 볼륨 할인" 이라고
  적혀 있는데, 어느 티어에도 20% 차감으로 9,700원이 나오지 않는다
  (A 7,900→6,320 / B 14,900→11,920). 구현은 문서 §3.1 의 계산식을 따랐다.
  예시 숫자가 오기인지 확인 필요.

- **활성 판정 (A) 조건이 두 문서에서 다르다. 매출에 직결된다.**

  기준이며, 03번 `billing_cycles` 에 열람 카운트 컬럼이 없다.
