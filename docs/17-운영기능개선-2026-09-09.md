# 운영 기능 개선 기록

후속 작업에서 의존성 복구·최종 빌드·DB 검증을 완료하고 학생 수강료·정산 관리를 추가했다. 아래는 당시 기록이며, 최신 상태는 [18번 문서](./18-수강정산교재구현-2026-09-09.md)를 따른다.

2026-09-09. 16번 문서의 점검 사항을 기준으로 진행한 로컬 구현이다. 운영 배포·PG 실승인·전문가 교재 검수 완료 기록이 아니다.

## 구현한 변경

- 인증된 강사 ID를 요청 본문으로 덮어쓸 수 없도록 학생 등록·카드 등록 입력을 명시적으로 제한했다. 브라우저가 넘긴 빌링키를 곧바로 저장하는 기존 경로는 차단하고 PG 인증 정보 교환으로 변경했다.
- 학습 단원 진도와 실제 수업 횟수를 구분했다. 재수행은 같은 단원을 유지하며, 사용료 판단은 수업 횟수를 사용한다. 미완료 수업의 재요청은 같은 수업을 반환한다. 리포트 중복 제출은 복습 카드와 알림을 중복 생성하지 않는다.
- 예약 연결을 수업 시작 트랜잭션 안으로 옮겼다. 실제 단원 메타데이터를 수업 시작 시 upsert하여 개발 시드 한 건에 의존하지 않도록 했다.
- 복귀 수업 시간 합계를 50분으로 수정하고, 기한 도래 카드와 완료 카드의 중복 집계를 제거했다. 현재 수치는 복습 기한 상태 비율이며 특정 기간의 학습 이행률을 직접 측정한 값은 아니다.
- `/training`에 6개 모듈, 모의 수업, 확인 문제, 서버 진도 저장을 추가했다. 교실 영어 250문장을 검색하고 학생 등록 전에 교안을 열어 연습할 수 있다. 완료는 자기 점검이며 자격 인증이 아니다.
- `/workbook` 학생 교재에서 14개 미션의 문항·말하기 자기 점검·메모를 서버에 저장한다. 강사는 학생 상세에서 이를 확인한다. 공개 `/learn`의 익명 브라우저 진도와는 별개이며 익명 기록을 자동 계정 귀속시키지 않는다.
- 학생 앱에 누락된 학습노트 API 경로를 연결했다. 초대 링크 페이지는 API에서 세션 쿠키를 발급받도록 변경했다. 서버 컴포넌트에서 쿠키를 변경하던 오류 경로를 제거했다.
- 정규 교안 71~250차시 180개 초안을 추가했다. 단원별 상황·목표 표현·질문·답변·어휘·수행 과제는 별도로 작성했고, 지도 방식에는 공통 6단계 틀을 사용한다. 전체 250차시와 슬라이드가 연결되며 검수 완료로 표시하지 않는다.
- 기존 생활 삽화 6종은 학생 교재에서도 사용한다. 360개 별도 이미지 카탈로그를 실제 생성 완료로 바꾸지 않았다. 발음 도해와 개별 전문 장면은 별도 제작·검수 범위가 남아 있다.

## 결제와 알림 구현

`PaymentOrder`, `BillingMandate`, `LearningProgress`, `TeacherTraining` 테이블과 Notification 재시도 필드를 추가했다. 거래 ID 고유 제약을 추가하고 크레딧 갱신·청구서 생성·잠금 처리에서 동시성 방어를 보강했다.

- 강사 청구 화면에서 충전 주문 생성, 미납 청구서 결제, 자동결제 카드 인증, 주문 내역, 미사용 충전 전액 환불 요청을 진행한다.
- 서버의 주문 금액과 PG 응답의 주문 ID·금액·통화를 비교한다. 결제 성공 뒤 지연된 실패 이벤트로 상태를 되돌리지 않는다.
- 주문서형 결제 승인, 빌링키 발급·자동 청구, 거래 재조회, 전액 취소 API 어댑터를 추가했다. 네트워크 결과가 불분명하면 같은 주문과 멱등키로 재확인한다.
- Toss 웹훅의 본문 상태를 그대로 믿지 않고 서버 인증으로 거래를 다시 조회한다.
- 충전 승인·취소는 중복 반영하지 않도록 처리한다. 환불 중인 금액은 먼저 예약 차감하고, 외부 결과가 불분명하면 재확인할 수 있도록 상태를 유지한다.
- 결제 수집과 메일 발송 작업을 cron에 연결했다. 메일 작업은 lease, 제한된 재시도, 제공자 멱등키를 사용한다.

공식 연동 근거: [Toss 결제 API](https://docs.tosspayments.com/reference), [주문서형 결제](https://docs.tosspayments.com/guides/v2/payment-widget/integration), [자동결제](https://docs.tosspayments.com/guides/v2/billing/integration), [Resend 발송 API](https://resend.com/docs/api-reference/emails/send-email).

## 운영 활성화에 필요한 외부 정보

- 일반 결제용 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`와 별도 자동결제 계약 키 `TOSS_BILLING_CLIENT_KEY`, `TOSS_BILLING_SECRET_KEY`.
- 라이브 결제는 `PAYMENTS_LIVE_ENABLED=true`를 별도로 설정하기 전까지 차단한다. 이 작업에서는 설정하지 않았다.
- 메일은 인증된 발신 도메인, `RESEND_API_KEY`, `MAIL_FROM`, `MAIL_ENABLED=true`가 필요하다. 실제 발송은 실행하지 않았다.
- 새 마이그레이션을 검증한 뒤 운영 DB에 적용해야 한다. 기존 pg_tid 중복이 있으면 고유 제약 생성이 실패하므로 거래를 먼저 대조해야 한다. 임의로 거래를 삭제하지 않는다.
- 학생 수강료의 판매자·수금 주체·강사 정산 방식은 사용자에게 확인을 요청했다. 현재 구현한 PG 흐름은 강사가 플랫폼에 내는 이용료·크레딧이다. 학생 수강료 수금·강사 송금 완료로 오해하면 안 된다.
- 정규 250차시, 교실 영어, 발음 자료는 교육 전문가 검수와 실제 초보 강사 시범수업 검증이 필요하다.

## 검증 기록과 재현

- 권한·진도·금액 검증·결제 상태 회귀 테스트를 추가한 시점에 **303개 테스트가 통과**했다. 이후 추가한 180차시와 최종 변경까지 포함한 최종 통과 기록으로 사용하면 안 된다.
- 두 앱의 초기 개선 빌드는 컴파일·타입 검사를 통과했으나 page-data 작업이 시간 초과되었다. 빌드 worker 수를 2개로 제한했다.
- 테스트 도구 설치 중 의존성 복구가 필요해졌다. 복구와 최종 빌드·통합 검증이 끝나기 전에는 배포하지 않는다.
- 기존 보관 디렉터리에서 Rollup·PostCSS·일부 esbuild 의존성을 복구했지만 최종 Vitest 실행은 esbuild 프로세스 시작 단계에서 `spawn EFTYPE`으로 실패했다. 테스트 본문은 실행되지 않았다. 현재 설치 상태를 정상으로 간주할 수 없다. 불완전한 디렉터리는 `node_modules` 안의 `.codex-*` 이름으로 보존했으며, 원본 lockfile에 따른 의존성 재설치와 검증이 필요하다.
- 결제 승인 응답의 주문 ID·금액·통화뿐 아니라 요청한 paymentKey까지 대조하도록 보강했다. 이를 검증하는 두 회귀 테스트도 추가했지만 위 환경 오류로 실행하지 못했다.
- `tools/check-operations-db.ts`는 기존 .env를 읽지 않고 메모리 DB에 새 마이그레이션을 적용하여 등록·인증·재수행·리포트 중복·결제 반영·학생 학습 저장을 검사하도록 작성했다. 실행 성공 여부는 별도 결과 JSON이 생성되었는지 확인해야 한다.
- DB 검증 도구는 `output/operations-db`에 PGlite 0.3.2 및 pglite-socket 0.0.7을 별도로 설치한 뒤 `node --import tsx tools/check-operations-db.ts`로 실행한다. [공식 PGlite Socket 문서](https://pglite.dev/docs/pglite-socket)의 단일 연결 제한상 운영 다중 연결 경쟁 조건을 검증하는 도구는 아니다.

최종 재검증 명령: `npm.cmd test`, `npm.cmd run typecheck`, 두 앱의 `npm.cmd run build --workspace ...`, DB 검증 도구, 학습·학습노트 브라우저 검사, 디자인·라이선스·화이트라벨 게이트.
