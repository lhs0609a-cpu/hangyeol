# 10 · 기술 아키텍처

## 1. 설계 제약 (전부 사업 요구에서 나온 것)

```
C1  종량과금 0원      학생 수에 비례해 늘어나는 API 비용을 만들지 않는다
C2  자료는 못 빼간다   다운로드 불가 · 서버 합성 워터마크 · 서명 URL
C3  화이트라벨 분리    학생 도메인에서 브랜드가 새지 않게 물리적으로 분리
C4  시각은 전부 UTC    학생이 전 세계에 있다. 여기서 버그 나면 과금 분쟁
C5  과금은 멱등        배치 재실행이 중복 청구를 만들면 안 된다
```

## 2. 스택

| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트(강사) | Next.js 14 App Router + TypeScript | SSR로 자료 URL 은닉 |
| 프론트(학생) | Next.js 별도 앱 (`note.` 서브도메인) | C3 물리 분리 |
| 스타일 | Tailwind + CSS 변수 토큰 | 06번 문서 토큰 그대로 |
| 백엔드 | Node.js (NestJS) 또는 Next Route Handlers | 초기엔 후자로 단일 배포 |
| DB | PostgreSQL 15 (Supabase 또는 RDS) | 03번 스키마 |
| 캐시·큐 | Redis (BullMQ) | 배치·알림 큐 |
| 스토리지 | S3 호환 (R2 권장) | 이그레스 무료 → 음원 대량 서빙에 유리 |
| CDN | Cloudflare | 서명 URL · 이미지 변환 |
| 인증 | 자체 JWT + 매직링크 | 학생은 비밀번호 없음 |
| 결제 | 자사 PG 빌링키 | 대표 보유 인프라 활용 |
| 메일 | Resend 또는 SES | 매직링크·알림 |
| 알림톡 | 카카오 비즈메시지 | 강사 대상 (창구 오픈 알림) |
| 모니터링 | Sentry + 자체 지표 대시보드 | |

**초기엔 모놀리스로 간다.** Next.js 하나 + Postgres + Redis + R2. 마이크로서비스 금지.


> 학생 앱 빌드 파이프라인에 브랜드 문자열 grep 검사를 넣는다. 발견 시 빌드 실패.

## 4. 종량과금 통제 (C1)

### 제거한 것

| 기능 | 원래 원가 | 조치 | 최종 |
|---|---|---|---|
| 수업 녹취 STT | $1.2/학생/월 | **전면 제거** → 강사 3분 입력 | 0 |
| 실시간 자막·번역 | $1.3/학생/월 | **초기 제외** → 교실영어 250문장 | 0 |
| 자유 대화 AI | $2.1/학생/월 | 시나리오 트리로 대체 | ~0 |
| HVPT 음원 | — | 사전 생성 캐싱 | 0 |
| 발화 비율 측정 | STT 필요 | **볼륨 레벨만 사용** | 0 |

### 남는 변동비

```
시나리오 판정 LLM   룰 매칭 90% 처리 → 세션당 1~2회 호출
                    학생당 월 $0.05 이하
알림 메일           학생당 월 5~10건
스토리지·대역폭     R2 이그레스 무료

→ 학생 1,000명 기준 월 API 비용 10만원 미만
```

### 가드레일 (코드 레벨)

```ts
// 런타임 TTS 호출 금지
if (process.env.NODE_ENV === 'production' && isRuntimeTTS(call)) {
  throw new Error('TTS must be pre-generated and cached');
}

// 학생당 일일 LLM 호출 상한
const DAILY_LLM_CAP = 20;   // 초과 시 룰 판정으로만 폴백

// 시나리오 드릴 일일 상한
const DAILY_DRILL_MINUTES = 15;
```

**PR 체크리스트에 "새 종량과금 API 추가 여부" 항목을 넣는다.** 있으면 반려.

## 5. 자산 파이프라인 (C2)

```
[원본 슬라이드]  내부 편집기 · L1별 버전
        │
   빌드 배치 (수동 트리거)
        ▼
[이미지 시퀀스] 1600×900 webp, 페이지별
        │
   요청 시점
        ▼
[워터마크 합성] sharp — 학생명·강사명·날짜 우하단 + 대각선 반복
        │
        ▼
[서명 URL 발급] TTL 300초, student_id·teacher_id 바인딩
        │
        ▼
[뷰어 렌더]     user-select:none, 컨텍스트메뉴·Ctrl+S/P 차단
```

### 합성 캐싱

같은 (unit, page, student) 조합은 24시간 캐싱한다. 매 요청 합성하면 CPU가 터진다.
캐시 키: `wm:{unitId}:{page}:{studentId}:{yyyymmdd}`

### 음원

```
HVPT     약 416개 사전 생성 → R2 → CDN. 불변
시나리오 유닛별 배치 생성 → R2. tts_generated_at 기록
모델대화 제작 시 업로드
전부 immutable. 런타임 생성 없음
```

## 6. 배치 작업

| 작업 | 주기 | 내용 | 멱등 |
|---|---|---|---|
| `cycle-close` | 매일 KST 03:00 | 만료 주기 활성 판정 → billable / waived | `closed_at IS NULL` 조건 |
| `invoice-create` | 매월 1일 KST 00:00 | billable 주기 합산 → invoice + PG 청구 | `uq_invoice(teacher, month)` |
| `payment-retry` | 매일 KST 10:00 | failed invoice 재시도 (최대 3회) | retry_count |
| `lock-enforce` | 매일 KST 04:00 | grace 만료 → locked 전환 | 상태 기반 |
| `srs-notify` | 매시 정각 | due 카드 알림 발송 | notifications.sent_at |
| `langgate-check` | 매주 월 KST 09:00 | italki 오픈 언어 크롤링 → 변화 시 알림 | 스냅샷 비교 |
| `strand-rollup` | 매일 KST 05:00 | 주간 Four Strands 집계 | upsert |

### 멱등성 원칙 (C5)

```
· 모든 배치는 재실행해도 결과가 같아야 한다
· cycle-close 는 period_end 기준 소급 처리 (실행 시각 무관)
· 새 주기 period_start = 직전 period_end  ← now() 금지
  now() 로 하면 배치 지연만큼 주기가 밀려 연간 청구 횟수가 줄어든다
· invoice 는 (teacher_id, billing_month) 유니크로 중복 차단
· PG 웹훅은 pg_tid 멱등키로 중복 무시
```

## 7. 타임존 처리 (C4)

```
저장    전부 timestamptz, UTC
계산    28일 = 정확히 28×24시간 (DST 무관)
표시    강사 → teacher.timezone / 학생 → 브라우저 TZ
배치    KST 기준 스케줄, 내부 계산은 UTC
"오늘"  학생 화면의 "오늘의 학습"은 학생 로컬 자정 기준
        → 서버는 학생 TZ 오프셋을 받아 계산
```

**여기서 버그가 나면 과금 분쟁이 된다.** 모든 날짜 계산에 유닛 테스트를 붙인다.

## 8. 성능 목표

| 항목 | 목표 |
|---|---|
| 강사 홈 LCP | < 1.5s |
| 학생 노트 LCP | < 1.2s (모바일 4G) |
| 자료 서명 URL 발급 | p95 < 200ms |
| 워터마크 합성 (캐시 미스) | p95 < 600ms |
| HVPT 음원 첫 재생 | < 300ms (프리로드) |
| API 일반 | p95 < 300ms |

HVPT는 다음 문항 음원을 **미리 프리페치**한다. 재생 지연이 훈련을 망친다.

`packages/billing` 은 **순수 함수로 작성**한다. DB 없이 테스트 가능해야 05번 TC 14개를 빠르게 돌린다.
