# 실제 수행에 따른 교재 조정

강사 교수 플랜의 ‘실제 수행 확인 · 교재 조정’에서 읽기, 듣기·이해, 말하기를 각각 혼자 가능/도움 필요/아직 어려움으로 기록한다. 관찰 근거를 입력하면 서버가 유지/부분 보충/재배정을 추천한다. 추천은 규칙 기반의 보조 판단이며 강사가 진행 방식과 단원 목표를 확인한 뒤 적용한다.

부분 보충은 원래 다음 단원을 복귀 지점으로 저장한다. 보충 수업 리포트가 재수행이면 같은 보충 단원을 반복한다. 도움 없이 수행했다는 강사 확인과 통과 리포트가 함께 있어야 원래 단원으로 돌아간다. 이미 진행 중인 보충 계획을 ‘유지’로 평가해도 복귀 지점을 잃지 않는다. 전반적으로 어려우면 강사가 더 쉬운 단원을 선택해 재배정하며 이후에는 해당 단원에서 순서대로 진행한다.

수업 리포트의 통과 하드코딩을 제거했다. 기본은 다시 연습이며 통과 선택 시 독립 수행 확인이 필요하다. 리포트 저장 후 교수 플랜의 조정 화면으로 이동한다. 진행 중인 수업을 덮어쓰지 않도록 리포트 완료 후에만 조정을 저장하며 다음 수업부터 적용한다.

교수 플랜, 수업 시작, 학생 교재의 단원 선택에 같은 보정 규칙을 사용한다. 학생에게는 ‘더 편하게 말하기 위한 기초 연습’으로 안내한다. 기존 진단, 수업, 교재 답안은 삭제하지 않으며 이전에 학습한 상위 단원도 다시 열 수 있다. 별도 보충 수업은 기존 수강권에서 실제 수업 1회로 차감된다. 단원 번호로 수강권이나 과금 횟수를 계산하지 않는다.

조정 이력은 기존 student_activity의 learning_adjustment, 독립 수행 확인은 learning_performance로 영속 저장한다. 신규 스키마 변경은 없다. 강사 조정·평가 이벤트는 학생 활동에 따른 과금 판정과 연속 학습일 집계에서 제외한다. 조정 이벤트에는 강사, 관찰 대상 수업, 세 영역 평가, 근거, 적용 방식, 단원, 복귀 지점과 요청 식별자를 남긴다. 동일 요청 재시도는 중복 저장하지 않으며, 오래된 화면의 변경은 차단한다. 학생 소유 강사 확인과 교사·학생 행 잠금으로 수업 시작과 조정을 직렬화한다. 학습 진도에 사용하므로 learning_adjustment 이력을 임의로 정리하면 안 된다.

검증: 단위 테스트와 격리 DB에서 부분 보충 반복, 독립 수행 없는 통과 거부, 원래 진도 복귀, 쉬운 단원 재배정 후 진행, 과거 기록 보존, 중복 및 오래된 요청 차단을 확인했다. 실제 PostgreSQL의 부하·동시성 벤치마크와 실제 학습자의 교육 효과 검증은 별도다. 운영 배포는 수행하지 않았다.

## 최종 검증 상태

- 기능 테스트: 27개 파일, 323개 테스트 통과.
- 격리 DB 통합 검증: 10개 통과. 교재 조정 흐름과 조정 이벤트의 과금·학습일 집계 제외, 실제 수업 횟수 기준 과금 유예 판정을 포함한다.
- 최종 타입 검사, 디자인 검사, 화이트라벨 검사 통과.
- 교재 조정 UI를 포함한 초기 두 앱 빌드는 통과했다. 이후 과금·활동 집계 보완을 반영한 최종 빌드는 로컬에서 작업자 60초 시간 초과와 긴 실행 지연이 반복됐다. 대기 시간 확대 및 단일 작업자 재시도도 완료하지 못해 검증용 프로세스를 종료했다. 시도했던 빌드 설정은 원래대로 복원했다.
- 이번 교재 조정 기능의 최종 브라우저 통합 검증은 미완료다. tools/check-live-commerce.mjs에 모바일 관찰 입력, 과거형 20차시 추천, 확인 후 저장, 독립 수행 체크와 211차시 복귀 검증을 추가했지만 이 변경 후의 실행 결과는 아직 없다. 기존 live-commerce-results.json은 이전 구현의 결과이므로 이번 기능의 검증 근거로 사용하지 않는다.
- 운영 배포 및 실제 학생·결제 데이터 변경은 수행하지 않았다.
